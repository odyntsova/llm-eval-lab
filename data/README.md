# Golden dataset: що це і як читати

`golden_dataset.json` — це набір тестових питань для чат-бота GadgetHub. Кожен запис — один сценарій: питання клієнта і те, яку відповідь ми очікуємо.

**Важливо:** політика GadgetHub (`refund_policy.md`) вигадана для навчання. Очікувані відповіді написані на її основі, тому вони перевіряють узгодженість бота з цим текстом, а не з правилами реальної компанії.

## Поля запису

| Поле | Що означає |
|---|---|
| `id` | Коротка назва сценарію. Має бути унікальною. Використовується як назва тесту. |
| `category` | Тип сценарію (див. нижче). |
| `source` | На який пункт `refund_policy.md` спирається очікування. Якщо пункту немає, тут написано, чому. |
| `input` | Питання, яке отримує бот. |
| `expected_output` | Еталонна відповідь. Це приклад хорошої відповіді, а не точний текст, який має повторити бот. |
| `criteria` | Список того, що має бути в відповіді. Суддя (Haiku) перевіряє відповідь саме за цим списком. |
| `must_contain` | Слова, які мають бути в відповіді дослівно. Якщо список порожній, цю перевірку пропускаємо. |

## Категорії

- **policy_fact** — пряме питання про пункт політики (наприклад, строк повернення).
- **policy_application** — треба застосувати кілька пунктів до конкретної ситуації (наприклад, відкритий ноутбук через 10 днів).
- **hallucination_trap** — питання про те, чого в політиці немає. Бот не має це вигадувати.
- **insufficient_info** — замало даних для відповіді. Бот має уточнити.
- **out_of_scope** — тема поза політикою. Бот має чесно сказати, що не знає.
- **prompt_injection** — клієнт намагається змусити бота ігнорувати правила.

## Як це використовується

`tests/test_golden_dataset.py` робить для кожного запису два тести:

1. **`test_must_contain`** — перевіряє, чи є слова з `must_contain` у відповіді бота. Це проста перевірка рядка.
2. **`test_answer_meets_criteria`** — суддя (Haiku) оцінює відповідь за `criteria`. Поріг 0.7. Це платна перевірка: вона викликає API.

## Як додати або змінити сценарій

1. Знайдіть пункт у `refund_policy.md`, на який спирається сценарій, і запишіть його в `source`.
2. Якщо пункту немає, поставте в `source` пояснення, чому (`None. ...`).
3. Не вигадуйте правила, яких немає в політиці. Якщо потрібне нове правило, спочатку додайте його в `refund_policy.md`.
4. Перевірте, що JSON коректний: `python3 -m json.tool data/golden_dataset.json > /dev/null`.
